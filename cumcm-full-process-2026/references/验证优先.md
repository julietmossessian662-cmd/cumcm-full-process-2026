## 一、两个实证案例

### 案例 1：把"射线带"当成"平行带" → 错误的平行四边形模型

**错误推理链**：示向度有 ±ε 误差 → "误差带" → 带相交 → **平行四边形** → 套用"对角线互相平分"→ 证明"以直径为直径的圆能覆盖"。

**事实**：两条边界射线**共用起点**（θ−ε 与 θ+ε 都从检测点出发），它们**不平行**，构成**楔形**而非平行带。
四个顶点由 4 条射线两两相交得到，构成的是一般四边形。**1500 例随机几何中 0 例**满足平行四边形判定（叉积相对量容差 1e-3）。

**正确结论**：
- 直径算法不受影响（暴力枚举 / 凸包+旋转卡壳对任意凸多边形都成立；实测两算法相对误差 **0**）。
- 覆盖性要重述为**充要条件**：以直径对 AB 为直径的圆覆盖区域 ⟺ 其余每个顶点 X 满足 **∠AXB ≤ 90°**（Thales 定理）⟺ 最小包围圆半径 R = D/2。
- 数值统计（1500 例）：**99.47% 成立；0.53% 不成立，最大只超出 0.0585%**。
- 论文写法：**"充要条件 + 反例 + 定量统计"**，而不是单字"能/不能"。

**教训**：**"带"这个词诱导了错误类比**。凡是把一个对象"看成另一个熟悉对象"的步骤，都要单独验证。

### 案例 2：直觉"正交化最优" → 优化结论方向性错误

**错误结论**："第二检测点应放在垂直侧翼（ψ=90°），因为两带交角接近 90° 时定位区域最方正。"

**事实**：以定位区域面积/直径为目标时，
```
A(ψ,d;L₁) = 4ε²L₁L₂/sinφ ,  sinφ = d·sinψ/L₂
∂A/∂d = 0 ⟹ d = L₁   ✓（基线=源距 是对的）
代入 ⟹ A_min(ψ) = 8ε²L₁²·tan(ψ/2)  ⟹ 随 ψ 单调递增
```
**ψ=90° 反而是最差的方向**；ψ 越小越优（直到退化）。

**但更关键的修正**：L₁（源距）是未知量 ⟹ "L₁ 已知时的最优"是**退化答案**（=把第二个检测点直接放到源上）。
**正确的 formulation 是鲁棒（min-max）优化**：对每个候选 (ψ,d) 取 L₁∈[5,1500] 的**最坏情形**，再选最优。

数值结论（可供同类问题参考量级）：
- 按最坏直径：**ψ≈45°、d≈1500m** → 最坏直径 83.6 m
- 按最坏面积：ψ≈20°、d≈1300m → 最坏面积 1133 m²
- 候选区域：ψ∈[30°,60°]、d∈[1300,1500]
- 迭代细化：两次测向 → 区域直径 52.4 m；第三次观测（走近后）→ **2.9 m**（收缩约 18×）⟹ 三次观测后精度远优于 20m 门限

**教训**：判据不同最优不同（面积 vs 直径）；**"已知量"若是未知量，解析最优立刻失去意义** → 必须改写成鲁棒/期望形式并说明取舍（这本身就是论文的"选择—对比—取舍"叙事素材）。

**补充（对拍评审后的口径统一，2026-09-11）**：平行版本（队友）提出"**让交会角接近 90°，条件数最低**"——这条**定性原则是对的**（经典测量学结论）。我方"ψ=90°"之所以错，是**混用了两个名字相近的量**：
- **ψ** = 第二检测点相对第一站示向度方向的**偏角**（我方数值优化的变量）
- **φ** = 两条视线在**源处**的**交会角**（经典结论里的变量）

两者的关系：ψ=90°（垂直侧翼）只给出 **φ=45°**；而鲁棒最优 ψ≈45°、d≈1500 对应 **φ≈93°**（L₁=1000）——**正是"接近正交"**。
⟹ 两条结论其实说的是同一件事：**对方给了正确的原则，我方数值给了该原则下的落点**。
**通用教训**：当结论被质疑时，先检查双方是否在描述**同名不同义的两个量**（偏角 vs 交会角、面积 vs 直径）；对拍中最有价值的产出往往是这种"口径统一"，而不是谁对谁错。

## 二、可复用脚本模式（三件套）

```python
# ① 独立方法交叉验证：同一量的两种算法/两种推导必须对拍
d_brute    = max(dist(v[i], v[j]) for i<j)         # 暴力枚举
d_calipers = rotating_calipers(convex_hull(V))     # 凸包+旋转卡壳
assert abs(d_brute - d_calipers) / d_brute < 1e-9  # 报相对误差，不报"成功/失败"

# ② 蒙特卡洛批量：随机几何/参数跑 N 千例，统计"结论成立率"与"最大越界幅度"
max_viol_rel = -inf
for _ in range(N):
    ...生成随机几何...
    v = 实测值 - 理论上界
    max_viol_rel = max(max_viol_rel, v / scale)
    fail += (v > max(1e-6, scale * 1e-9))          # 相对容差！
```

```python
# ③ 解析最优 vs 网格搜索（含"退化检测"）
best = min(((psi, d) for psi in range(2, 91, 2) for d in range(50, 2001, 25)),
           key=lambda p: objective(*p))
if best.psi <= 4 or best.d <= 75:
    print("⚠️ 最优落在网格边界 → 可能是退化解，检查是否需要鲁棒化")
```

**精确子问题的枚举法**（比迭代法更可信，适合 4 点以下）：
最小包围圆（MEC）对 n≤4 点可**精确枚举**：所有两点（作直径）+ 所有三点（外接圆）→ 取能覆盖全集的最小者。
**R = D/2 ⟺ 直径对给出的圆恰好覆盖全集** —— 这就是"以直径为直径的圆能否覆盖"的严格判据。

## 三、实现坑（都真实踩过，会静默给出错误数字）

| 坑 | 后果 | 正解 |
|---|---|---|
| 四边形顶点按"参数顺序"当多边形顺序 | 鞋带公式算成自交**蝴蝶结**，面积差 57 倍 | 按**重心极角排序**后再算面积 |
| 在平行四边形内采样用 `A + u(B−A) + v(C−A)` | C 与 A 不相邻 → 采样区域放大一倍 → 批量判定全错 | 用**相邻顶点**：`A + u(B−A) + v(D−A)` |
| 带宽用弧度近似 `2εL` 但几何用精确交点 | 公式与几何差 0.17%（O(ε) 阶） | 明示这是近似公式并给出相对误差；精确值用 `2L·tanε` |
| 批量判定用绝对容差 1e-6 | 长条/极端几何（D 可达 1e5 m）下大批误报"失败" | 用**相对容差** + 报告最大越界幅度 |
| 把绝对累计量当增量比（自检脚本） | 断言全错，浪费一轮 | 断言**增量** Δ，且避免在"目标已被修改后"再验证目标行为 |

## 五、修正后的全库同步与交付卫生（2026-09-11 二轮实战）

修正一个结论后，收尾不是"改掉那一处"，而是三层动作：

1. **全库扫描**：用旧错误概念关键词（如 `平行四边形`、`ψ=90`、错误日期）grep 整个知识库。覆盖范围必须含：专题方案 / **阶段交付物**（拆解表、设计理念、模型选型）/ **复盘日志与统计行** / 检查清单 / 看板。
   ⚠️ 实战：第一轮只修了 4 处"明显"引用，第二轮又扫出 7 处残留（拆解表 ×2、设计理念 ×2、选型 ×1、复盘 ×2）——**第一轮几乎必然漏，要预期二轮**。
2. **区分命中类型**：修正记录/警示标注里的旧概念＝历史留痕，保留；正文裸引用＝残留，必须改。改写时保留修正痕迹（写"一般四边形（非平行四边形）"这类），让后来的读者知道有过这坑。
3. **交付前复扫（硬规则）**：把库里内容交给队友/外发（复制到聊天、汇编成册）之前，**重新跑一次全库扫描**并确认只剩标注上下文——交付物必须 100% 修正版，否则已推翻的结论会扩散进并行工作流。交付时附一句："已核对，本文为数值验证后的修正版（共修正 N 处）"。

工具提示（Windows/git-bash 实测）：Unicode 密集的验证（emoji 计数等）用 **Python 脚本文件**读取统计（grep 对 emoji 计数不可靠）；**验证逻辑落盘成 `.py` 再跑**，不要 `python -c` 内联（bash 先做命令替换/转义，中文与反引号会被吞掉→syntax error）。
