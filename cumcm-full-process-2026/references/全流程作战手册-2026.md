# CUMCM 全流程作战手册（v1.0 · 技能内正式版）

> 定位：一次「四天冲刺、首次参赛」完整实战的复盘提炼——面向下一届参赛者，也面向未来的我们。
> 使用：本版为 Hermes 技能 `cumcm-full-process-2026` 内正式版（v1.0，2026-09-15 由草稿 v0.1 审定迁入）；公开版发布前过 §10 红线 + 队友确认。
> 配套资产：论文工程骨架 `templates/论文骨架/`（主文件/导言区/摘要页/章节占位/编译脚本）；通用脚本 `scripts/`（图表、渲染目检、文本审校、支撑材料打包、知网检索）。LaTeX 环境与编译细节见技能 `chinese-latex-papers`。
> 脱敏声明：全文不含队号 / 学校 / 赛区 / 姓名 / 账号 / 官方加密日志等身份信息；案例数字仅保留可公开的统计。

## 0. 一页速览

| 阶段 | 时间 | 核心动作 | 一句话原则 |
|---|---|---|---|
| 备赛 | 赛前 | 知识库、历年论文逆向、模板与工具链预建 | 把"重复劳动"提前干掉 |
| 选题 | 开题当晚 | 三题预判 + 加权决策 | 用"评委视角"选题，不用"我会不会"选题 |
| 建模 | 第 1–2 天 | 拆问 → 设计 → 实现 → 验证 | 任何直觉结论先过数值验证 |
| 论文 | 第 2–3 天 | 模板套写、先成稿再打磨 | 论文是赛程的一部分，不是赛后作业 |
| 定稿 | 最后 24h | 结构冻结、细节打磨、门禁检查 | 最后一晚只校对，不改结构 |
| 提交 | 截止日 | MD5 流程、上传、凭证、归档 | 每一步留物证 |

## 1. 备赛期（赛前）

- **知识库先行**：建一个库（如 Obsidian）分五层：主页 / 流程规则 / 赛题 / 方法论 / 复盘。经验当晚落库——中断可恢复、多会话不打架。
- **历年获奖论文逆向**：把目标题型的往年论文 OCR 入库 → 先"预判"优秀论文应有什么 → 再读论文找差异 → 提炼"评奖因子"，用于选题与写作。
- **模板与工具链预建**：论文 LaTeX 模板、图表生成脚本、代码排版、Word 转换管线——比赛期间直接套用，不现造。
- **硬约束盘点（开题 2 小时内）**：账号、设备限制、正式测试/提交次数、时间窗口——摸清并写成检查表。**教训：资源限制没摸清，差点在最后一天翻车。**
- **死线日历化**：所有截止时间列成表；日期必须用日历核对（曾把"周日截止"误推晚一天，白丢半天）。

## 2. 选题之夜

- **三题通读 + 预判**：每道题先写"如果我评奖，我会看什么"。
- **加权决策法**（对"评委/获奖视角"打分，不做能力视角）：分题竞争格局 / 客观硬指标与验证可行性 / 四问完整性 / 论文可写性 / 创新点提炼难度 / 合规风险。
- **敏感性复核**：权重扰动后结论不变才定稿；决策过程留档（为什么选它、为什么不选）。
- 当晚产出：选题结论 + 理由 + 各题速览（为复盘留素材）。

## 3. 分工与协作（AI 时代）

- **三角色**：主脑（接口契约+审查）/ 独立第二版 / 文档成稿（不依赖设备的章节先开写）。
- **双版本独立 + 对拍**：两版互不看实现，完成后用**固定种子**的对拍台比较——独立性就是纠错冗余。（实例：两处独立错误被互抓，双方合起来才是完整答案。）
- **仿真台（Mock）的诚实边界**：计时与协议层可信（可被真机日志反算验证）；物理假设层必须以真机校准为准——**分层交代可信度，别把 Mock 成绩当正式成绩**。
- **协作记忆**：每晚更新"状态页"（版本、数据口径、缺口、下一步）；新会话从记忆入口接续；所有结论标注"来源+验证状态"。

## 4. AI 协同流水线

- **分工**：代码生成（推理模型）/ 逻辑与数学审查（另一模型）/ 中文成稿（中文强模型）/ 配图 / 统筹 Agent（记忆、审计、打包）。
- **AI 互审**：一模型出稿、另一模型独立挑错（论文同法：初稿丢给另一模型找逻辑漏洞）。
- **留痕**：如实记录工具名称/版本、用途环节、提示方式、采纳与核验方式——这是 AI 合规申报的素材。
- **AI 合规三条**（以当届最新规定为准）：论文参考文献前放「AI 工具使用声明」；支撑材料按规定附「AI 工具使用详情」；如实描述、人工核验（虚假声明是取消评奖级红线）。

## 5. 建模与验证（工程化）

- **顺序纪律**：审题 → 问题拆解 → 解题设计 → 执行 → 论文转化（不跳步）。
- **数值验证闭环**：所有解析结论先写脚本验证（实例：两处"听起来很对"的直觉结论被推翻；"类比对"是最危险的一步）。**错误发现得越早成本越低。**
- **审计驱动优化**：拿到运行日志先反算成本结构（实例：审计发现"移动"占时间大头 → 策略优先级重排，效率翻倍）。
- **两层测试策略**：不限次的"演练"攒统计（分布、灵敏度、不确定度）；稀缺的"正式"次数留给冻结版。
- **数据口径**：演练 / 正式 / 仿真 分开标注，绝不混用。

## 6. 论文工程（LaTeX 流水线 + 定稿纪律）

- **结构模板**：摘要 → 问题重述与分析 → 假设 → 符号 → 基础模型 → 逐问模型 → 分析与验证 → 模型评价 → 推广 → 参考文献 → 附录（支撑材料目录）。可直接复用 `templates/论文骨架/`。
- **摘要红线**：一页装下；最后写；数字写实。
- **观感**：正文宋体 + 西文/数字 Times + 数学字体统一；语言口述化、简单化。
- **定稿"四件套"纪律**（每轮修改都跑一遍）：① 断言唯一匹配的批改脚本 → ② 全量重编（0 错误 / 0 Overfull / 0 缺字）→ ③ 全文文本提取核查（旧引用清零、新引用就位）→ ④ 关键页渲染目检；每轮换装留档 + 记录 md5。
- **改动管理**：结构性改动（标题 / 编号 / 附录 / 关键词）提前 24h 完成；最后一晚只做细节与校对。

### 6.5 细节打磨清单（评委观感 · 实战中逐条打磨过，★ 别漏）

- **关键词**：用"文献高频常用词"（弃生造词）；排版上"关键词"三字与正文协调、词条字体与正文一致。
- **附录结构**：删冗余附录；保留「核心程序清单（节选）」——只截取核心问题的核心代码（**思想核心、少而精，让评委看懂要点，不求全面**）；完整源码放支撑材料承载。
- **支撑材料目录（附录 A）**：条目要让评委一眼看到「主程序」；关键文件命名直接体现身份（如 `01_主程序_xxx`、`主程序_xxx.py`）。
- **标题层级**：同类问题归并到大标题下（如"模型的建立"统摄各问），小节重编号后**全量映射**所有交叉引用（正文+附录一起查，旧串清零、新串就位）。
- **表达**：口述化、去冗余；劣势描述少而缓。
- **AI 声明**：置于参考文献之前；条目简洁如实。

## 7. 合规红线条目表（提交前逐条核对）

- 首页 = 摘要页（页数限制按当届规范：正文 ≤30 页；附录策略按当届规范）。
- 电子版命名口径（当届手册为准；无格式要求时采用"不含队伍信息"口径）。
- 查重与原创：AI 文本个性化改写；引用只收已核实条目。
- 队号纪律：提交物凡出现队伍数据只用正式队号；素材来源账号、内部编号零残留。
- 时间线：MD5 截止 → 冻结（此后文件不能再动）→ 上传窗口。
- 上传门禁清单化（二三十项，逐条打勾）。

## 8. 提交日 playbook

- **T-24h**：结构冻结；列出"只允许改动"清单（错别字、数字校对）。
- **MD5 流程**：生成 → 与本地计算核对 → 提交"选题+MD5" → **此后任何写入都会导致无法上传**。
- **上传**：按窗口时间上传电子文件；账号限制（通常仅队长账号）提前确认。
- **凭证与归档（一步到位）**：① MD5 成功页截图；② 提交成功页截图；③ 终版双件；④ 提交清单——统一放入归档目录（例：`Documents\<赛事>\proof\ + backup\<时间戳>\`）。
- **纸质版（如赛区要求）**：承诺书 + 编号页按模板手填，附录一并打印。

## 9. 坑与教训（速查）

- 死线日期一律日历核验，勿用"周X"反推。
- 备份后立即校验落点再报成功。
- 配置/环境变更后立即验证连通（一次接口配置写坏可瘫痪半天）。
- 工具链坑要沉淀成表：LaTeX 缺字 / Overfull / 编译误判、转义吞字、路径风格坑……
- 收尾必留痕：截图 + 终版 + 清单三件套同日归档。
- 时间账启示：高强度冲刺下，**流程化（脚本+清单+核对）比灵感可靠**。

## 10. 公开脱敏红线（本手册及一切公开物适用）

- **不入公开物**：队号、学校、赛区、姓名（队员/教师）、平台账号、加密日志与任何官方回执、赛题原件与官方附件、未获授权的第三方材料。
- **团队共同成果**：公开前征得全体成员同意；署名方式由团队定。
- **引用规范**：公开案例时只放可公开统计；他人方法注明出处。
- **发布检查**：全文关键词扫描（姓名/校名/编号/账号模式）+ 人工通读一遍再 push。
